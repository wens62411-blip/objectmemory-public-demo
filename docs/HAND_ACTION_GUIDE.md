# 手部动作：当前实现和验证边界

本轮实际通过项、失败重测和仍未验证事项见 [专项结果](HAND_ACTION_REPORT.md)。

这一模块使用已经安装的本地 MediaPipe 手部模型，不上传家庭画面，不引入第二个全帧模型。手关键点、手势几何和手物交互是三个不同层次，不能相互冒充。

## 使用

1. 在实时页启动已有摄像头，直接查看“手部动作”卡，无需打开诊断。
2. 设置中的“启用本地手部分析”决定是否分析手。“显示手部关键点”只决定显示辅助线，隐藏它不会重启摄像头或关闭分析。
3. 尚未注册物品照片也可查看张手、握拳、捏合、指向、四指展开及画面内移动方向。姿态不清楚时显示未知；不强行分类。
4. 要关联某件物品，需要先注册并确认该物品照片，再让实时画面中的物体通过照片身份校验。普通候选框不能自动借用“我的手机”的身份。

## 动作与证据

| 显示 | 实际含义 |
|---|---|
| 张手 / 握拳 / 捏合 / 指向 / 四指展开 | 多帧关键点投影的几何解释，不证明接触或握住物体 |
| 手在物品附近 | 画面内距离接近，不能说拿起 |
| 连续共同移动 · 可能携带 | 同一只持续跟踪的手与已识别物体连续同向位移，仍是二维运动线索 |
| 持有状态不确定 | 曾有共同移动，当前静止、掉手、遮挡或模型失败；不能说放下 |
| 释放候选 | 同一只手可见分离，正在等待物体重新稳定 |
| 已观测可见分离 | 连续分离与稳定满足门槛；确认放下仍须完整物体移动、已确认支撑面及对应媒体证据 |

方向以来源画面为准，不是世界坐标。当前仅支持两只手；不会从照片推断深度、力、接触压力或真实握持。

## 来源与失败处理

- `GET /api/cameras/{id}/actions` 只读取当前推理结果，无新线程、无新摄像头、无 JPEG 传输。
- 每条动作带 `source_session_id`、`source_frame` 与源时间；与对应物体必须属于同一帧。
- 服务重启、换源、断档、镜头或档案变化会重建动作基线。旧动作不沿用为新放置证据。
- 手部模型、手势分析或交互分析失败时，物品的可靠观察仍可保存；错误不会变成“释放”。
- 当前状态中的交互字段由服务器同帧对象覆盖，不信任回调携带的自行声明。
- 显示过期时撤下动作，不重复把同一帧当成持续动作。REAL/DEMO/TEST 继续使用各自数据库和来源标识。

## 默认门槛

所有阈值集中在 `SettingsInput` 与两个分析模块默认表中，API 可配置且有范围与一致性检查，不在前端改判定。

- 手身份和姿势：至少 3 帧、0.2 秒；姿势稳定和身份稳定分开。
- 手物共同运动：至少 4 个连续位移步、0.45 秒、总位移 0.035（来源归一化坐标），同向且相对距离受限。
- 可见释放：至少 4 帧、0.6 秒，物体稳定；只保留短时有效证明。
- 两次连续输入间隔超过 0.75 秒会断开动作连续性。
- 手历史默认最多 12 个点；物体交互状态有数量和过期上限，无每帧数据库或截图记录。

## 验证材料如何解读

`data/verification/hand-postures.json` 是公开静态图片及其人工变换，证明真实本地模型、框坐标、几何反馈接通，不是物理拿放准确率。`hand-actions-http-result.json`（测试临时目录中产生，汇总报告会摘录）是实际文件视频→真实后端→动作接口→独立 SQLite，未伪造模型或业务响应。

本轮合成序列覆盖旁边手经过、共同移动、静止手持、掉手、可见释放、遮挡、重连、第二次拿放、帧重放和异常。实际电脑摄像头的运行采样仅能证明采样期间输出了哪些动作与帧率，不自动证明人做完了一次指定的拿起放下。
