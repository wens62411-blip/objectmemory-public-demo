# 摄像头设置与证据边界

## 先选择运行模式

- 日常真实使用：用 `Start.bat` 或 `scripts/start.ps1` 启动 `REAL`。
- 合成视频、虚拟 ESP32 或无硬件演示：只用 `Start-No-Hardware-Demo.bat`。
- 自动化测试：由 `scripts/test.ps1` 创建 `TEST` 临时数据根。

模式在进程启动时确定。请勿在同一进程里把测试视频配置改名为“家庭摄像头”；REAL 会拒绝模拟来源。

## 电脑摄像头

1. 关闭会议软件、相机应用和其他占用同一设备的程序。
2. 在 Windows“设置 → 隐私和安全性 → 相机”允许桌面应用访问摄像头。
3. 在 ObjectMemory 的摄像头页添加“电脑摄像头”，先尝试索引 `0`。
4. 点击“测试连接”。后端会尝试 DirectShow、Media Foundation 和 OpenCV 默认后端，并且必须实际读到可解码帧才报告成功。
5. 已有相同编号时直接使用已有摄像头，不能重复创建后争抢同一设备。保存时勾选启用才明确启动；单独改名称或房间不会启动/重启。
6. 实时页区分采集帧率、画面帧率与识别频率。默认预览目标 30 FPS、识别约 5 次/秒，目标值不是实测保证。请求摄像头输出 30 FPS 不等于驱动一定支持，页面显示真实测量。

预览使用与识别独立的单帧缓存与单编码线程，页面刷新和多订阅者不重复打开摄像头，MJPEG 不靠重复发送同一源帧凑帧率。预览不会把旧检测框贴到新帧上；确认事件取证仍沿原识别帧、轨迹和证据门，不因提高预览速度放宽。

历史初次审计曾在索引 `0`、MSMF、1280×720 下记录 54,003 帧和 1,800.047 秒长跑，产物为 `audit/runtime-stability.json`；这些不是本阶段结果，也不证明物品识别成功。OpenCV 索引本身不是物理设备身份凭证。

本阶段首次长跑实际完成 1,800.109 秒，但 **30 门中有 2 门失败**：隔离库出现 1 条未确认 `last_seen` 当前状态，而 movement 和事件媒体均为 0，空搜索不再满足预期。原始触发帧没有保存，不能据此确认具体误识别画面；后续取帧也不能替代该帧。原始失败完整保留在 [本阶段首次长跑](../audit/p0-real/runtime-stability-first-attempt.json)。

普通观察写入门和丢失状态计时修补后的 [第二次长跑原件](../audit/p0-real/runtime-stability-second-attempt.json) 实际完成 **1,800.125 秒，29/30 门通过**。movement、当前状态、轨迹和事件媒体均为 0，没有触发异常帧留存；摄像头释放门通过。唯一失败为 `backend_stopped_cleanly`：`graceful=false`、退出码 1，日志停在 `Shutting down`。该失败原件保留，不以最终通过覆盖。

退出修复后的 [第三次正式长跑](../audit/p0-real/runtime-stability.json) 已完成：**soak 1,800.094 秒，总观察 1,808.812 秒，30/30 门通过，`errors=[]`**。movement、当前状态、轨迹和事件媒体均为 0；后端正常退出 `graceful=true`、退出码 0，摄像头释放通过，隔离临时数据已清理。这证明本次本机 OpenCV 取流与运行稳定性检查通过，不证明真实物品移动闭环已验收，也不覆盖长跑期间未执行的人工纠正等操作。

本阶段分类测试统一汇入 `audit/p0-real/final-test-results.json`。异常诊断最多保存 3 张 API 源帧及对应 JSON；不能原子对应触发帧时必须标记 `not_same_frame`。P0 实物移动套件的 14 个场景仍为 `NOT_RUN`；“摄像头在线”不等于“物品识别成功”。

若设备忙，先停止 ObjectMemory 中使用该索引的摄像头，再运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\camera-diagnose.ps1"
```

报告写入 `data/diagnostics`。页面快速诊断复用已有取流状态；没有运行源时才做有总时限的后台探测，可查看进度或取消。完整诊断是额外排障，不是添加摄像头的必经步骤。诊断截图不是 movement 事件证据。

## 手机 Marker 页与局域网地址

真实移动向导的手机地址现由后端 preflight 从当前服务进程实际监听且已验证的 LAN 候选地址生成，不依赖前端传入 Host 或任意 URL。未启用局域网监听时后端不提供 LAN 地址；电脑上的 localhost 页面仍不能直接供手机访问。已开启 LAN 监听也不证明手机、防火墙与路由器已端到端可达。

手机页可使用 `/companion/validation-marker?item={item_id}&camera={camera_id}`，不需要先创建 suite 或 run。向导和设置共用本机生成的真实二维码，保留标记页必要的 item/camera/run 参数，不携带访问码或任意外部地址。没有可用 LAN 地址时明确提示开启局域网，不使用二维码占位。手机仍需同一局域网和主机 8 位访问码。打开显示页不启动验收、不采集手机摄像头；只有真实后端帧能改变识别状态。

## 浏览器摄像头

浏览器摄像头由用户点击后调用 `getUserMedia`；浏览器授权的 JPEG 帧经 WebSocket 发送到当前会话对应的后端摄像头实例。浏览器权限不能由普通自动化静默授予，所以测试可模拟权限，但不得 Mock 最终事件 API。

浏览器推帧限制单帧 2 MB、最大 3840×2160，并校验会话和 Origin。同一摄像头只接受当前发送者；页面退出、轨道结束或 WebSocket 失败时会停止帧泵和媒体轨道。

浏览器摄像头属于 `browser_camera`，在 REAL 中仍需通过同一事件证据门。仅看见本地预览不等于服务器持续收帧，更不等于产生确认位置。

## RTSP、MJPEG 和 ONVIF

当前网络源只接受 URL 主机为字面量私有、回环或链路本地 IP；域名、公网地址和跨数据目录路径会被拒绝。这是 SSRF 防护，不是自动发现功能。

| 类型 | 典型用途 | 当前事实 |
|---|---|---|
| RTSP | 局域网 IPC/摄像头 | 通过 OpenCV 拉流，未对具体家用型号做本轮真机验收 |
| MJPEG | ESP32 或 HTTP 摄像头 | 解析 multipart/JPEG，未对真实板做本轮验收 |
| ONVIF | 获取局域网设备配置/流地址 | 只支持显式地址，没有后台扫网；未做本轮真机验收 |

不要把摄像头用户名、密码写进名称或截图。日志脱敏会遮盖常见凭据，但本地 SQLite 和进程内配置仍应按敏感数据保护。

## 授权屏幕矩形

屏幕采集不是任意桌面录屏。用户必须在本机创建一次性授权，确认固定矩形后才能启动；授权绑定当前会话并在约 120 秒后过期。来源显示为 `authorized_screen_capture`。

只选择包含受控摄像头预览的最小矩形。被其他窗口遮挡、窗口移动、缩放或通知弹出都会改变像素，可能破坏证据连续性。未经用户选择的区域不得采集。

## 视频文件

视频文件是 `DEMO`/`TEST` 来源，归一化为 `video_file` 且 `is_simulated=true`。REAL 不接受视频上传或启动。文件回放和循环事件必须保存在 DEMO/TEST 数据库，页面持续显示测试视频标签。

DEMO 上传限制由后端执行：允许的视频扩展名、最大 512 MB、先写临时文件再原子移动。通过扩展名和可打开性不代表视频内容真实。

## ESP32-CAM

真实设备只有完成物理串口识别、固件上传、配网、设备注册/心跳和视频流验收后才可显示为真实硬件。虚拟 ESP32 只能在 DEMO/TEST 启动，来源为 `virtual_esp32`，不会成为 REAL 证据。详见 [硬件说明](HARDWARE.md)。

## ArUco 标签模式

当前最可重复的身份识别路径使用 OpenCV `DICT_4X4_50`：

1. 为物品分配唯一 ID 0–49。
2. 以 100% 比例打印 `demo/markers/aruco-markers-a4.svg` 或单独 PNG，保留完整白色边界。
3. 把标签固定在物品可见平面，避免反光、模糊和手部长期遮挡。
4. 为摄像头配置互不含糊的区域多边形。
5. 让物品在旧位置稳定，再移动并在新位置重新稳定。

ArUco 是标签识别，不是无标签语义识别。实验检测器即使能画出候选框，也必须和注册物品身份及后续稳定轨迹结合，不能仅凭检测框创建 `placed`。

## 区域和阈值

区域坐标使用归一化画面坐标。区域重叠过大、边界紧贴物品或摄像头移动都会让 `from_zone`/`to_zone` 不可靠。摄像头位置固定后再绘制区域。

事件阈值集中在设置中，包括连续检测帧、稳定帧、最大帧间隔、最低置信度、稳定速度、抖动、跨区最小位移、同区最小位移、稳定时间、遮挡和丢失时间。修改阈值后应重新建立基线并重新做静止、微调、跨区和遮挡验收；不要为追求演示效果把门槛降到单帧触发。

## 故障判断

| 现象 | 先检查 | 不能据此声称 |
|---|---|---|
| 测试连接成功 | 是否持续读取变化帧、是否释放设备 | 已识别物品 |
| 实时页有画面 | 来源标签、帧时间是否前进 | 已生成真实事件 |
| 有检测框 | item ID、轨迹和区域是否稳定 | 已确认放下 |
| 视频循环产生事件 | 是否 DEMO、是否新 source session、是否去重 | 真实摄像头成功 |
| 虚拟设备在线 | `source_type=virtual_esp32` | 物理 ESP32 在线 |
| 固件构建成功 | manifest 和二进制哈希 | 真机刷写成功 |

摄像头断开后状态应变为离线，旧帧不得继续推进状态机。重连会建立新来源会话和稳定基线；如果断开本身产生 movement，请保留诊断报告并视为 P0 真实性错误。
