### 实际修复

- **P1，原有缺陷：上传批次不一致。** `apps/api/app/registration.py` 先完成校验和本批新媒体准备，再由 `apps/api/app/db.py::save_many` 在同一事务保存全部参考图及档案版本。第二/第三张插入、档案更新或媒体写入失败均清理本批新媒体、回滚新行，既有参考图片及旧档案不受影响。真实 SQLite trigger 复现了旧版“文件被删除、数据库行仍在”的错误。
- **P1，原有防护缺口：请求来源校验。** `apps/api/app/security.py` 拒绝未知域名、重复或畸形 Host，异常 Origin 不再抛 500，HTTP/WS 均校验协议和来源。只支持 localhost、字面量回环/局域网 IP；不接受机器名或 `.local`。当前固定 Starlette 1.6 已防住旧版 URL 路径混淆，不能声称本轮成功绕过登录；scope path 是额外加固。参考 [Starlette 官方安全公告](https://github.com/Kludex/starlette/security/advisories/GHSA-86qp-5c8j-p5mr) 与 [Host 中间件说明](https://www.starlette.io/middleware/#trustedhostmiddleware)。
- **P2，PR 新增回归：懒加载失败白屏。** `apps/web/src/components/PageBoundary.tsx` 将页面失败隔离，导航与 REAL/DEMO 标识保持可见；用户明确重新加载，不自动重放注册或刷写请求。
- **P2，原有可选路径缺陷：YOLO 解码。** `services/vision/detectors/experimental.py` 修复单框维度丢失、85 列 objectness 误当类别、非有限坐标和裁剪后框中心。8 个新增用例在原 PR 全失败，修复后通过。默认 NanoDet 未换模型或降低阈值；[YOLOv5 官方解码语义](https://raw.githubusercontent.com/ultralytics/yolov5/v7.0/utils/general.py) 与实测相符。
- **P2，测试可复现性。** REAL/DEMO Playwright 和二维码解码测试支持 `OM_E2E_PYTHON`；默认项目虚拟环境不变。REAL/DEMO 的 ASGI 测试显式使用 localhost，不为测试方便放宽生产 Host 白名单。媒体测试解码完整 8 帧并验证顺序，不再只看首帧。

### 独立性能对照

基线为 `14777c3`，合成独立数据，预热一次、七次中位数；以下是直接 Python 调用，不含网络，也不是摄像头 FPS。

| 场景 | 基线 | 集成版本 | 附加验证 |
| --- | ---: | ---: | --- |
| 100 物品、600 参考图批量加载 | 255.225 ms | 5.681 ms | SELECT 201 → 3，返回值一致 |
| 10,000 条含轨迹事件的健康计数 | 651.847 ms | 3.049 ms | SQL 聚合不加载/解码轨迹，计数一致 |
| 1,000 物品末尾精确命中搜索 | 3.484 ms | 0.975 ms | 匹配结果一致 |

另有 300 组搜索与基线同值；500 组位置输入中，基线正常返回的 306 组同值，其他 194 组基线本身空值异常，不计作等价通过。真实本机 DINO 模型对 6 组合成输入输出最大绝对差 0；实际 NanoDet 的 1,845 个候选框和分数差 0。100 次外观预处理局部中位数 2.7387 → 2.2106 ms，测量时其他测试并行，不能作为独占设备基准。最终入口 gzip 78.58 KB；独立 Scene3D chunk 553.32 KB 的构建警告仍在。
