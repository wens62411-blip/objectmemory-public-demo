# 手部动作专项结果 · 2026-09-06

结论：已在当前 ObjectMemory 内实现并运行本地手部动作反馈和保守的手物交互判断，未另建 Demo。代码、数据与测试边界分别核对；尚未完成用户实物的标注拿放准确率验收。完整机器可读结果见 [hand-actions-result.json](../data/verification/hand-actions-result.json)。

## 实际修复

- P0：原 `show_hands` 同时关闭推理，当前用户设置正好为 false。现拆为 `hand_detection_enabled` 与纯显示开关；隐藏关键点、无变化保存均不重启摄像头。
- P1：设置页将 GET 元数据带回严格 PATCH，实际浏览器保存返回 422。前端现在只发送其拥有的设置字段，后端仍严格校验。
- P1：新模块第一版误读手部 XYWH 框为 XYXY；修正了真实接口和测试输入，增加右半画面及真实 MediaPipe 公共图验证。没有把错误 fixture 的通过当作成功。
- P0：邻近不再当作持有。多帧手身份、姿态、方向和手物共同移动分别判断；手丢失、静止手持、遮挡不自动变为放下。
- P0：释放证明绑定共同运动和分离的来源会话、帧区间与有效计数。第二次拿放重新建立证明；已完成释放过期后不会永久恢复旧持有状态；尚未释放时仍不能猜测放下。
- P0：动作/模型健康读取异常不会阻断可靠物品观察；旧 release 不复用。状态回调不能自报持有/释放，服务器使用本帧引擎证明。
- P1：首轮完整回归暴露遮挡帧覆盖历史交互的问题。现保留 `last_observed.interaction`，另用 `current_interaction` 表达缺失期间状态，截图和原观察时间不变。
- P2：旧 `possibly_held` 只代表邻近，读取时降为 `nearby`，不做破坏性数据迁移。普通 UI 使用左/右手或简短序号，不展示长内部 ID。

## 帧率与真实数据

五分钟中位采集 29.95 FPS、预览 28.5 FPS、识别 5.42 次/秒。599 个样本中有 149 个预览低于 20 FPS，最低 14.11；这 149 个样本采集端也低于 20 FPS。没有出现采集高于 25 而预览低于 20 的样本。因此不能声称全程达到 20 FPS，也不能把所有低帧都归因于手部分析。尚未确定采集端降帧的具体硬件/曝光原因。

最终代际短测中位采集 30.015、预览 28.73、识别 5.47；这些只是当次窗口，不是全天保证。环形证据缓冲为 35 帧/24,192,000 字节，仍有界。没有进行本轮最终版本的 30 分钟负载验证。

目前 REAL 数据库：1 个物品，0 张参考照片、0 个识别档案、0 个移动事件、0 条当前物品状态、0 个事件媒体。用户的“我的手机”尚未有照片身份依据，不能用手势或通用框补出手机位置。物品关联链路由代码与合成回归验证，但本轮真实相机没有完成手机拿放。
