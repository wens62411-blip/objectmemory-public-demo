## 已确认的断点与修复

| 断点 | 修复与边界 |
| --- | --- |
| 参考框和档案失效不是同一事务；构建可能先标记 ready、后验证失败 | 目标框与失效状态原子更新；裁剪与特征先暂存，正式 matcher 验证后一次提交完整档案；失败清理本次派生文件，不删原照片 |
| 本地注册验证器加载被混同于正在运行的摄像头加载 | 区分 validated_profile_version 和实际引擎 loaded_profile_version；页面分别显示图片保存、建档、引擎加载和现场验证 |
| 档案失败或重建时，旧媒体任务仍可能提交旧身份 | building/失败/取消均刷新引擎；清除旧 generation 候选；媒体编码后短锁复核引擎代次，SQLite 提交事务内再次核对 ready 档案版本 |
| 更新的移动/离开状态可能被旧 last_observed 时间遮蔽 | 搜索使用最新有效状态；截图仍保留其真实拍摄时间和来源，不篡改成新帧 |
| 新来源会话第一次真实观察仍被旧截图的“放下五秒”条件阻挡 | 新会话首次通过观察门即保存同帧截图；同会话位置变动的截图仍受稳定条件控制，不升级成确认放下 |
| 参考局部定位异常可能清空正常物品候选，而手部模块继续运行 | 正式推理分阶段隔离错误，保留正常候选，独立显示出错阶段；本次现场未观察到该异常，不将其冒称为本次漏检的已证实原因 |
| 摄像头重连后最近生成的结果可能实际属于旧会话 | 识别结果同时核对来源会话、重连代次和档案版本 |
| 浏览器迟到授权/编码/旧 WebSocket 关闭可能干扰新采集 | 摄像头代次与 socket 归属检查；停止/后台时释放轨道；只接受当前待确认帧的 ACK；实际握手超时明确报错 |
| 正式后台重启后旧页面长期显示 UNKNOWN，刷新才恢复 | 401 后仅同源 GET/HEAD 可合并重建会话并重读一次；POST/PATCH/DELETE 不重放；局域网未认证仍返回访问码页面。已在同一个正式页面和独立 TEST 重启回归验证 |
| 全量回归发现新搜索投影清掉旧版 hand_near 弱提示 | 保留没有新帧、新来源、新事件的 legacy nearby；绝不沿用旧手持或释放证据。原失败测试不改，新增 9 种组合回归 |

正式物品模型和手部模型均在本机 Python 视觉服务中执行，收到同一来源帧。物品检测、参考匹配先于手部处理；本次未发现“只运行手部，根本没运行物品模型”。新增同帧诊断将“模型未执行”“执行了无物品候选”“有候选但身份未确认”分开。

## 运行与小幅性能优化

`runtime-30min.json` 为部署新修复前、同机真实摄像头和真实模型的 1807.76 秒基线，共 179 次采样；其中有并行测试负载且用户曾移动摄像头，不是受控静止手机或最终代码连续运行验收。

| 热身后指标 | 中位数 | 范围 |
| --- | ---: | ---: |
| 采集 FPS | 30.645 | 22.78–31.38 |
| 预览 FPS | 23.39 | 20.31–30.24 |
| 物品推理 FPS | 3.33 | 1.33–4.39 |
| 识别延迟 | 297.65 ms | 232.4–415.7 ms |

进程持续存活，事件 0→0；采样工作集 719,405,056→395,624,448 字节，私有内存 1,683,144,704→1,695,612,928 字节，线程 176→174，句柄 1288→1305。这是有限时间的实测，不能据此保证没有长期泄漏。

进一步检查发现 4 个参考查询窗口已合并为一次 ONNX 批处理，模型和注册特征已缓存，未发现每帧重复加载。只将 BGR→RGB 的 NumPy 拷贝换成已有 OpenCV 转换，输入张量逐值一致，不改模型、窗口、阈值或观察时钟。

交错配对 A/B 中，1280×720 两类输入预处理 p50 从约 35 ms 降到 25–26 ms，高分辨率拍屏输入从 259–273 ms 降到 201–212 ms；整帧耗时并非全部改善，不能称为解决 30 FPS 推理。154 个受影响回归通过，4 类正式模型回放的候选、框、分数和拒绝理由与优化前完全一致。见 `preprocess-ab-result.json`、`preprocess-regression.xml`、`post-rgb-optimization/result.json`。

部署 RGB 优化后的 301.41 秒真实摄像头检查共 59 次采样，截图均可解码、事件仍 0→0；采集/预览/推理 FPS 中位数分别 30.56/25.18/3.66，识别延迟中位数 275.8 ms。与此前 30 分钟的场景及并行负载不同，不能用两段数值计算严格因果提速率。该段并非放置手机五分钟的受控测试。

此段资源出现一次阶跃：线程 151/154/153→201/200/199，私有内存约 1512/1515/1515→1589/1592/1589 MiB。开始时人物模型未加载，随后已加载且处理过帧；与既有按需加载逻辑相符，但没有原生分配时间对齐证据，不能认定全部阶跃都来自该模型，亦不能声明已排除长期泄漏。原始记录为 `runtime-final-5min.json`。
