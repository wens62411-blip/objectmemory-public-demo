# 手机识别专项修复实测报告

日期：2026-09-06。工作区：现有 ObjectMemory；分支：`codex/photo-memory-core`。

**状态：自动修复、回归和已确认缓存清理已执行；用户自己的手机识别与真实拿放验收未完成，连续 30 分钟稳定性未通过，不能称为成熟产品或全部修好。** 数字以 `data/verification/phone-recognition-result.json` 及其指向的原始回执为准。各套测试存在重叠，不能把数字相加当作独立试验次数。

## 1. 原先为什么上传后没有反应、没有位置

- 照片实际已经保存、建立本地特征并加载到摄像头；这不等于现场已找到该物品。旧提示把这些状态说得过于接近。
- NanoDet 接入缺少其 RGB、等比例补边和逆坐标还原契约，已经修复并执行对应测试。不过单独修它仍未在用户原参考图找到手机，不能说这是唯一原因。
- 原 DINO 输入采用中心裁切，会丢失长条物品两端；已经更改为保留完整物体的 fit224 黑色补边，并提升预处理版本，不能混用旧特征。
- 相机当时主要缺少手机类别候选；少量候选的身份分数也未通过门槛。因此不写位置是拒绝未经确认身份，不是可以随意补一条“在桌面”的空缺。
- 上传后的刷新失败曾影响成功反馈，物品/搜索页面也没有持续刷新最后位置。现在保留写入成功回执，读取失败单独提示，并使用有界、可取消的串行刷新。

## 2. 当前模型与手机外形功能

- 类别候选：本地 OpenCV Zoo NanoDet，RGB、等比补边至 416，再还原原图坐标。
- 注册身份：本地 DINOv2 small，384 维、CPUExecutionProvider；权重 SHA-256 为 `f22797eabf810a75e41de68d378541ebea372122b25c4ce3ef25ff618250c20a`。模型/预处理版本见 `services/vision/detectors/appearance-model.json`。
- 新预处理：RGB、最长边缩至 224、居中黑边补齐、归一化、CLS 特征、L2；不是声称上游默认预处理就是这一方法。
- 身份阈值仍为 0.82、差距门仍为 0.06，没有为制造识别成功降低阈值。
- 手机外形补充：本地有界轮廓方法，默认最多 3 个候选，最长处理边 640。**只显示“外形像手机 · 未确认”，不运行身份匹配、不更新位置、不生成事件。** 黑矩形、屏幕、遥控器也可能满足外形条件，外形分数不是概率。
- 曾评估的 YOLOX、YOLOv8n 没有改善本次参考图检出，未接入生产；两份未采用权重及附属说明已清除，下载来源与哈希仍保留在回执中。

## 3. 用户照片如何进入识别

上传/抓拍 → 原图和显示图 → 用户确认目标裁剪 → 本地参考特征 → 带版本的识别档案 → 运行摄像头加载该版本 → 原始帧类别候选 → 候选裁剪身份匹配 → 连续观察 → 最后看到状态及必要截图。

用户已有 1 张确认参考图，档案已由 v6 重建为 v7；原图哈希未改变。重建前保留一份 SQLite 备份。证据见 `phone-profile-migration.json`；它不是识别准确率证明。

注册页区分图片已保存、档案就绪、相机已加载和现场身份已接受。辅助外形建议失败不会丢掉主检测建议；外形建议也不能消除“主模型尚未找到手机”的警告。

## 4. 手部与页面修复

手部显示开关与手部分析开关继续分离。本轮回归查出：嵌套配置默认值展开被误判为真实参数改变，只隐藏手部框也会重启摄像头。已通过有效配置归一化修复，旧空配置和部分配置也覆盖到测试。

桌面 ≥1100px 默认并列显示流畅预览和同帧识别；手机单列并提供“查看物品识别”锚点。检测框只对应实际解码的同一源帧；过期帧清框。外形来源即使异常携带 accepted=true，前端也不得显示注册身份接受。

这些修改不是新的真人手势准确率证明。手接近不等于拿起，丢手不等于放下，未可靠确认物品身份时不能推断其动作。

## 5. 无标签实测证据及不足

公开视频来源、许可和固定哈希在 `scripts/test-assets/`。这些视频只在独立 TEST 数据库运行，明确为文件回放，不是用户现场摄像头。

- Lotti/HTC 实拍回归：20 秒参考与 41/45/50/54 秒实际候选对照，旧中心裁切 0/4 达到门槛，新完整补边 4/4 达到门槛。此素材参与了故障定位，只是回归对照，**不是独立盲测准确率**。
- 实际 HTTP + FastAPI + SQLite 文件测试：单视角及两视角参考均能更新一条最后看到状态、一张观察截图、零确认移动；其他手机参考对照无身份接受。截图可解码、哈希和声明源帧经独立重读核对。
- 三台相似手机视频揭示离线 DINO 在部分屏幕状态下会混淆不同手机。因此不能把轮廓候选直接送身份通道。对应安全专项中，三台手机、另一台手机单独出现、黑矩形、遥控器形状都不允许被外形通道写成用户位置。
- 用户实际摄像头确有连续帧、真实模型与 v7 档案。最新 30.078 秒探测取得 59 个不同源帧，14 次外形候选、0 次注册身份接受；其中没有主模型确认的手机候选。采集 29.72 FPS、预览 28.72 FPS、识别 5.38 FPS。物品是否实际在镜头内尚无人确认，不能把外形候选说成 14 次真实手机识别。

## 6. 场景图与候选位置

本轮没有新增地图/深度/固件模块。已有场景图仍以摄像头区域为基础，家具模型建议需要用户确认可放置区域；没有标定不输出厘米，没有观察不编造位置。真实观察、手持/遮挡状态和可能区域继续分开。用户手机尚无可靠状态时，不应在图上制造一个标记。

## 7. 运行与存储

采集、预览和模型推理速率分别报告，不能把约 30 FPS 取帧写成 30 FPS AI 识别。新长跑使用实际已有摄像头与当前模型，但没有人确认手机一直在视野里时，只能证明运行稳定性，不能证明静止手机识别通过。

本次探测总耗时 1804.44 秒，310 次状态采样、309 个可解码且哈希不同的快照。记录覆盖 0.063–1572.781 秒，最后 **231.659 秒无相机采样**；最终在线相机统计为 0。Windows System 日志显示 13:47:05 因 Lid 进入新型待机，13:50:58 短暂退出待机，与缺口时间吻合。**本轮状态为 PARTIAL / CONTINUOUS_30MIN_NOT_VERIFIED**，不能使用 `completed=true` 证明连续运行达标。原始报告没有源时间戳；已修正后续探测保存该字段，并给汇总增加缺口、停帧、空样本和会话变化拒绝检查。

暖机后 300 个已记录样本：采集中位 30.01 FPS、最低 14.66；预览中位 28.67 FPS、最低 14.34，44 个样本低于 20 FPS；识别中位 5.38 FPS、最低 4.49；延迟中位 168.4 ms。**没有实现始终 20 FPS 预览，更没有实现 20 FPS 模型识别。** 约 26 分钟有效采样不覆盖电脑待机期间。

## 9. 最短使用方式

真实模式双击 `Start.bat`，打开 `http://127.0.0.1:8018`。确认 REAL，再在实时页启动已有相机。物品管理 → 管理照片/测试识别 → 确认目标框 → 建立/更新档案；有连续身份接受才应更新“最后看到”。

手机访问需同一可信局域网，使用现有局域网启动方式和管理员访问码；不能在手机上用 127.0.0.1 指向电脑。具体入口以设置页显示的本机地址为准。

演示模式仍使用 `Start-No-Hardware-Demo.bat`，独立数据库和媒体，不将其结果作为真实记录。
