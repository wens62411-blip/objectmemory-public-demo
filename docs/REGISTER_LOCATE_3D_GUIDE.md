## 用已有电脑摄像头

1. 普通启动使用 `Start.bat`，进入 REAL；`Start-No-Hardware-Demo.bat` 才是独立 DEMO。不要把演示数据库当家中实况。
2. “物品管理”上传清晰照片，确认完整物品范围。看到“照片已保存”并检查后台加载的档案版本；这不是物体已经被识别。现有用户手机参考与 v7 档案已保留，无需重复上传同一照片。
3. “实时监控”启动已有摄像头。主画面连续显示，诊断的模型原帧与手部关键点可展开。通用候选、注册照片局部匹配和已确认身份不同，纯轮廓不能更新可靠位置。
4. 多帧可靠身份观察后，先更新“最后看到”。拿起移动时持续跟踪；观察到手物分离并且物品连续稳定 **5 秒**，证据完整才保存确认移动。五秒内再拿起、遮挡或断流会取消等待，不猜“已经放下”。
5. 同位置继续观察不会每帧保存截图/录像。默认最近两次未固定移动历史加当前状态，固定事件受保护；原始注册图片不被自动清理。
6. 点击找物页语音按钮提问，或直接输入“我的手机在哪里”。回答应包含最后时间及摄像头画面方位。未知就说未知，不把最后看到说成确认放下。语音是主动单轮交互，不是持续唤醒助手。

09-08 晚间新服务真实电脑摄像头 WebSocket 30 秒解码 885 帧，约 29.48 FPS；独立浏览器桌面/窄屏可见换帧约 28.41/28.01 FPS，没有空白或重复叠图。它不是每秒重新识别次数，严格 30 FPS 未达标。模型计算默认最多四线程，可用 `OM_APPEARANCE_THREADS=1..4` 限制；本机五分钟识别中位约 3 FPS。浏览器摄像头上传另有 8 FPS 限制，390px 布局验收不是真手机性能。刷新旧页面可加载新界面，但会丢失未提交表单，请不要在输入密码后随意刷新。

## 接 XIAO ESP32S3 Sense / ESP32-CAM 后安装

设备中心有两个明确的固定目标，不能混刷：**Seeed XIAO ESP32S3 Sense（ESP32-S3、8 MB Flash，板上 USB-C）**，以及原来的 **AI Thinker ESP32-CAM（原版 ESP32、4 MB Flash，需匹配下载底板）**。其他 S3/C3 仍不支持。XIAO 用可传数据的 USB-C 线接电脑；ROM 芯片识别不能替代针脚/摄像头模块型号确认。

板型与配置依据：[Seeed 官方说明](https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/)和 [PlatformIO 固定板卡配置](https://docs.platformio.org/en/latest/boards/espressif32/seeed_xiao_esp32s3.html)。实际板上容量和摄像头状态仍须逐项读取，不由文档代替验收。

1. 开启已有的局域网服务入口，并让电脑和板卡连接同一可互通的 **2.4 GHz Wi-Fi**。设备中心选择正确的“开发板型号”，在本机页面填写后台局域网地址、Wi-Fi、设备名称和房间；不要把密码发到聊天，板卡也不能使用电脑的 `127.0.0.1`。
2. 接好唯一一块目标板，选择系统实际枚举的 USB 串口。09-08 本机读到的是 COM3；重插后编号可能变化，应以当前页面为准。蓝牙 COM5/COM6 不是这块板。多块候选板不自动探测/擦写；不凭端口名字猜芯片。
3. 在“绑定这块板，以后插入自动接入”确认型号、端口及覆盖原有固件，点击“绑定并开始自动安装”。这会开始实际安装，不只是保存设置。没有需要保留的原程序才授权。
4. 程序依次核对 ROM 芯片/MAC、所选板型的固定产物与镜像头/分区，刷入程序、配网、检查串口启动证明、关联摄像头。XIAO 的分区、启动地址和针脚均使用独立配置。看每个真实阶段，不把“编译成功”理解为“已刷入”，也不把“已注册”理解为“有视频”。
5. 同板同版本再次插入只恢复连接，不反复刷写。廉价无序列号 CH340 依赖同一个 USB 插口；换插口或换固件需要重新授权。失败/断电不会无限自动重刷。
6. Wi-Fi 信息只暂存于后台内存；首次配网未完成就重启后台，需要重新输入。无自动复位电路的底板可能仍需按 BOOT/RESET 或正确连接 GPIO0，由实际硬件决定。
7. 页面现在记忆所选板型，但不记忆密码或刷写授权。“热点兼容性检查”只读电脑连接及同名热点频段，不读取保存的密码。电脑连 5 GHz 不等于双频路由器没有 2.4 GHz；没有观测到 2.4 GHz 时，应检查手机**个人热点的 AP 频段**，关闭再开启热点后重新检查。不要把手机自身连接 Wi-Fi 的频段当作热点频段。
8. 已有刷写成功收据时，在恢复区重新输入网络设置并明确授权“只重新配网，不重刷”。写入状态不确定时，另需明确确认覆盖一次。恢复锁定同板 MAC、板型、固定固件哈希和绑定版本；刷新、旧请求或重插不能重复排队擦写。换固件必须重新授权。
9. 本轮尚未统一串行化板端备用 AP 网页配网与 USB 配网，请不要同时从这两个入口提交配置。界面/协议测试不代表该并发场景或真机网络已经验收。

## 手机上打开

电脑普通 `Start.bat` 默认只对本机提供服务。需要手机访问时，使用已有的“开启局域网访问”入口，或退出当前后台后从项目根运行：

```powershell
.venv\Scripts\python.exe -B -u scripts/serve.py --port 8018 --mode REAL --lan --no-browser
```

本轮已实际运行这一服务入口。手机与电脑连同一 Wi-Fi，在手机浏览器打开电脑设备页/启动提示显示的局域网地址并填写管理员访问码；不用手机的 localhost，也不要把访问码发到聊天里。HTTP 局域网下浏览器可能不允许直接调用手机摄像头/麦克风，远程看电脑流与手机采集是不同功能。

## 轻量三维场景

打开“场景地图”。无已有场景且允许自动生成时，从新鲜帧建立相对草稿并保存，刷新不会重复覆盖；有真实家具候选才建对应对象，没有就显示空草稿，不能凭空填桌子沙发。

可以旋转/缩放三维视角。若需要空间位置，需确认支撑面、尺寸/相对单位和各平面的四点对应，另用独立检查点验证；拖动浏览视角不是修改物理标定。无真实深度/接触证据时只给图像方位或区域，不保证厘米位置。历史静态 TEST 帧已通过一个沙发候选生成简化相对草稿的实际模型/WebGL 测试，仍不是新现场测量重建。
