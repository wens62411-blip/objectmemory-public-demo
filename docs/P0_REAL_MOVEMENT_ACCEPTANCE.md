# P0 真实物品移动验收

本阶段只验证一个受控闭环：电脑上的真实 OpenCV 摄像头观察一台真实手机，手机屏幕显示绑定到“我的手机”的 ArUco 标记；物品从画面内区域 A 移到区域 B 并重新稳定后，视觉管线最多写入一条 `REAL` movement，并由普通搜索从 REAL SQLite 返回区域 B。

这是一项“真实摄像头＋屏幕标记验证”，不是无标签识别验证。测试视频、浏览器自报、虚拟 ESP32、seed、fixture 和直接事件 API 均不能通过本验收。

## 使用步骤

1. 用电脑打开 `/acceptance/real-movement`。页面只在运行模式为 `REAL`、来源为 `opencv_camera`、连续帧健康且数据库为规范 REAL 数据库时允许开始。
2. 用手机浏览器打开页面给出的 `/companion/validation-marker` 地址，将屏幕亮度调高、关闭自动锁屏，并让标记周围保留完整白边。
3. 在电脑实时画面中画出不重叠的区域 A 和区域 B。区域坐标按视频宽高归一化保存。
4. 将真实手机稳定放在区域 A，等待视觉管线连续识别并建立基线。此阶段只更新当前状态，不创建 movement。
5. 按页面提示把手机移到区域 B 并放稳。只有同一 ArUco 身份真实离开 A、形成连续轨迹、进入 B 并再次稳定，才可能确认一条 movement。
6. 关闭验收页，从普通首页搜索“我的手机在哪里”。结果必须来自 REAL SQLite，而不是验收页状态。

## 通过门槛

- 物理手机和真实 OpenCV 摄像头均实际参与；
- `runtime_mode=REAL`、`source_type=opencv_camera`、`is_simulated=false`；
- `detection_mode=aruco_screen_validation`、`created_by=vision_pipeline`；
- 每个 `validation_run_id` 最多一条事件；
- 独立 before、after 图片和一段覆盖移动的短片均可解码且 SHA-256 匹配；
- 当前状态、事件和三份媒体属于同一 `source_session_id`；
- 静止、轻微调整、遮挡未重新出现、刷新、断流与重连不得制造确认事件；
- 10 次物理跨区试验至少 8 次正确，且 5 分钟静止误报为 0；
- MINIMAL 最终只保留每件物品最近两条未固定确认 movement，固定事件不删除。

未实际完成手机动作前，项目状态只能是 `TOOLING_READY` 或 `NOT_RUN`，不能写成 P0 通过。

## 固定套件与失败记录

所有轮次属于同一 `suite_id`，顺序为：静止 5 分钟、同区轻调、四次 A/B 交替移动、移动中遮挡、受控断开重连、六次 A/B 交替移动。共 14 轮、10 次移动、4 个负样本。后台冻结相机配置摘要、标记、区域多边形和阈值；相机配置变化或断流不能被当成移动。失败/取消/中断的轮次不可删除后补成功，不按 URL 中任意历史 ID 拼接通过率。

只有后端汇总认定合同完整、至少 8/10 次移动和 4/4 个负样本通过才达到软件门槛。页面刷新只读恢复。此门槛仍需现场操作者确认物理镜头和真实手机动作，自动化测试不能填写物理准确率。

遮挡后重新出现必须重新满足连续稳定窗口，不能沿用遮挡前的终点帧。录像必须有完整 5 秒前置与 5 秒后置；边界取实际连续帧，低帧率下一帧略晚于截止点不因此丢弃。终点确认和媒体保存完成前页面不显示通过。

## 最小保留与计分

四次确认变化后，MINIMAL 应只剩最近两条未固定事件及对应六份媒体文件；当前状态指向仍然保留的证据。按策略删除前完整核验的旧事件保留明确的完成回执，只用于历史计分。没有可信删除回执的缺失/篡改媒体不得保持成功计分。测试报告分别列“历史曾核验”和“当前仍可打开”，不把已删除文件列为当前证据路径。
