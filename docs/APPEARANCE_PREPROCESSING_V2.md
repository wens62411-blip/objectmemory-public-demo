# 完整物品外观预处理 v2

这是一次有界的照片身份匹配修复，不是更换识别权重，也不是实物准确率验收。

## 变更与兼容性

旧 v1 把短边缩放到256，再取中央224×224。对于259×128的长条参考框，缩放后长边518像素，只保留中间224像素，可能丢失物体两端。

v2 使用应用级完整物品预处理：BGR转RGB，Pillow BICUBIC等比缩放至最长边224，居中补黑边至224×224，再使用原RGB归一化、384维CLS与L2归一化。它**不是官方 BitImageProcessor 默认的中心裁切契约**。不做旋转增强，不更改生产相似度阈值0.82或多物品差距门0.06。

新版本：`8b1f705a3a7f6f062f6bdd21986c1583d3ef105d:onnx-fp32-cls-rgb-bicubic-fit224-blackpad-l2-v2`。

ONNX文件仍为88,532,934字节，SHA-256仍为 `f22797eabf810a75e41de68d378541ebea372122b25c4ce3ef25ff618250c20a`。无须为此重新下载权重。输入仍限制为uint8、三通道BGR、非空、最多16,777,216像素、长宽比不超过32；输出为连续float32 `[1,3,224,224]`。

旧v1向量不能改标签伪装成v2。匹配器按完整model_version拒绝旧档案。部署方应先备份，保留原始参考图与用户确认区域，用这些原有区域重新生成特征并递增档案版本，再由新进程加载。本模块修复不自动迁移或修改REAL档案。

## 支持变更的有限证据

离线实验只以公开Lotti视频20秒的一张参考图建档，41/45/50/54秒为独立测试帧，正样本框由实际NanoDet生成。旧中心裁切4帧均未达到0.82；完整物品补边4帧均通过，分数0.9070–0.9345。仅给旧中心裁切增加0/90/180/270参考方向没有改善这4帧。

三部其他手机在3个时间点的9个手工研究裁剪、8个背景裁剪均未被补边方案误接受。这些负样本仅检验DINO混淆；人工裁剪不是候选模型成功。补边仍不具备任意角度不变性，同图旋转控制不计独立准确率。

原始对照分数、视频SHA与CC-BY-SA来源保存在 `audit/p0-real/research-appearance-crops.json`；脚本的中心裁切分支固定为v1，避免生产升级后改变历史对照定义。该实验不证明用户手机、真实摄像头、拿起放下或普遍多视角识别通过。

## 回归范围

专项检查覆盖完整长条物体两端、RGB/补边/输入内存界限、v1档案拒绝、准备状态版本，以及上述公开正负样本。测试使用真实本地模型和文件帧，不用预置正样本候选、不修改REAL库。

本轮先保留失败结果 `data/verification/pytest-appearance-v2-red.xml`，修复后的专项结果为 `data/verification/pytest-appearance-v2-green.xml`。完整集成和用户实物验证仍须单独执行，不能用这些专项结果替代。
